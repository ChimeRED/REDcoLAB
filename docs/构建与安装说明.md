# REDcoLAB 构建与安装说明

- 项目：红红子LAB / REDcoLAB
- 目标：Clip Studio Paint 5.0 EX（Windows）
- 版本：1.0.0

---

## 1. 环境要求（本机实测值）

| 项 | 要求 | 本机实测 |
|---|---|---|
| 操作系统 | Windows 10/11 x64 | Windows |
| 编译器 | MinGW-w64 g++（支持 C++17） | WinLibs GCC **16.2.0** |
| Python | 3.x（仅用于测试脚本） | 3.12（`%LOCALAPPDATA%\redkolab-tools\python_path.txt` 记录） |
| PowerShell | 5.1（脚本按纯 ASCII 编写，兼容 5.1） | 5.1 |
| CSP | **EX 版** 5.0 | 本机 5.0.4 官方安装体 |
| CELSYS SDK | Triglav Plug-In SDK 头文件（见下） | 已放在 `sdk_official/`（不入库） |

> 官方样例工程需要 **MSVC + MFC**；本项目改用 **MinGW-w64**，无需安装 Visual Studio。
> 两条路线产出的都是导出 `TriglavPluginCall` 的 x64 DLL，已与 Celsys 自带滤镜的导出符号核对一致。

---

## 2. 取得官方 SDK 头文件（必须自己下载）

**这些文件不随仓库分发**（CELSYS 持有著作权，许可条款限制再分发）。

1. 打开官方页面：<https://www.clipstudio.net/ja/dl/cspsdk_term/>
2. 阅读并同意《CLIP STUDIO PAINT EX フィルタープラグインSDK使用許諾契約書》
3. 下载压缩包（当前版本文件名形如 `FilterPlugIn20210827.zip`）
4. 解压，把 `TriglavPlugIn*.h` 共 9 个头文件复制到：

   ```
   REDcoLAB\sdk_official\
   ```

需要的 9 个头文件（构建脚本会逐个检查，缺哪个报哪个）：

```
TriglavPlugInDefine.h            TriglavPlugInRecord.h
TriglavPlugInExtern.h            TriglavPlugInRecordFunction.h
TriglavPlugInMain.h              TriglavPlugInSDK.h
TriglavPlugInServer.h            TriglavPlugInService.h
TriglavPlugInType.h
```

> ⚠️ **不要**从第三方 GitHub 镜像或别的仓库下载这些头文件。
> 旧版 v0.1.6 就是这么做的（`native/fetch_sdk.ps1` 从一个第三方镜像拉取），
> 新版已移除该做法。

---

## 3. 安装编译器（仅首次）

```powershell
winget install -e --id BrechtSanders.WinLibs.POSIX.UCRT --scope user
```

装完后 `g++` 可能在 PATH 上，也可能在 `%LOCALAPPDATA%\Microsoft\WinGet\Packages\BrechtSanders.WinLibs*` 下
—— 构建脚本两种情况都会自动找到。

---

## 4. 构建

```powershell
cd REDcoLAB
powershell -NoProfile -ExecutionPolicy Bypass -File tools\build.ps1
```

脚本会：

1. 检查 `ai-toolkit/VERSION` 格式
2. 检查 9 个 SDK 头文件是否齐全（缺则给出官方下载指引并失败）
3. 找到 g++ 并打印版本
4. 以 `-Wall -Wextra -Werror` 编译（**零警告要求**）
5. 产出 **两个** 文件：
   - `dist\REDcoLAB.cpm`
   - `dist\REDcoLAB.dll`
6. 校验产物：是 x64 PE、且导出 `TriglavPluginCall`，并打印 SHA256

预期输出（实测）：

```
=== REDcoLAB build ===
version       : 1.0.0
sdk headers   : 9 present in sdk_official/
compiler      : ...\mingw64\bin\g++.exe
compiler ver  : g++.exe (MinGW-W64 x86_64-ucrt-posix-seh, built by Brecht Sanders, r2) 16.2.0
compiling -> REDcoLAB.cpm
compiling -> REDcoLAB.dll
built         : REDcoLAB.cpm  172032 bytes  x64  exports TriglavPluginCall  sha256=...
built         : REDcoLAB.dll  172032 bytes  x64  exports TriglavPluginCall  sha256=...

BUILD OK
```

> 为什么产出两种扩展名？因为 CSP 5.0.4 主程序里**找不到 `.cpm` 这个字面量**，
> 而 Celsys 自带滤镜全是 `PlugIn\PAINT\*.dll`。哪种能被加载需要真机实测确定。

## 5. 测试（不需要打开 CSP）

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\run_tests.ps1
```

它会用 `tools\mockhost.py`（模拟宿主）把插件跑完整个生命周期：

```
moduleInitialize -> filterInitialize -> filterRun -> filterTerminate -> moduleTerminate
```

并做客观断言：

- 所有已写入像素 **R == G == B**
- **Alpha 完全不变**
- 完全透明（alpha=0）的像素**未被修改**
- 登记的 `targetKinds` 正确
- 对缺失的宿主回调不崩溃

预期以 `RESULT: PASS` 和退出码 0 结束。

> **这个测试不能证明 CSP 会加载插件。** 它只证明 SDK 调用约定和灰度算法正确。

## 6. 安装到 CSP

```powershell
# 先看它会做什么（默认就是 dry run，不写任何文件）
powershell -NoProfile -ExecutionPolicy Bypass -File tools\install_plugin.ps1

# 确认后再真的写入
powershell -NoProfile -ExecutionPolicy Bypass -File tools\install_plugin.ps1 -Execute
```

脚本会把两种产物复制到**全部候选目录**，并打印每个绝对路径。候选目录及依据：

| 目录 | 依据 |
|---|---|
| `%APPDATA%\CELSYSUserData\CELSYS\CLIPStudioPlugIn\PAINT` | 本机已存在（空），由 CSP 自己创建 |
| `%APPDATA%\CELSYSUserData\CELSYS\CLIPStudioModule\PlugIn\PAINT\win` | 旧版使用；仍可能有效 |
| `%APPDATA%\CELSYSUserData\CELSYS\CLIPStudioModule\PlugIn\PAINT` | 同上，去掉 win 子目录 |
| `%USERPROFILE%\Documents\CELSYS\CLIPStudioModule\Plugin\PAINT` | 滤镜插件 SDK 文档所述位置 |
| `%USERPROFILE%\Documents\CELSYS\CLIPStudioPlugIn\PAINT` | 同上，另一种拼写 |
| `C:\build\csp\CLIP STUDIO 1.5\CLIP STUDIO PAINT\PlugIn\PAINT` | CSP 程序目录，Celsys 自带滤镜所在（可能需要管理员权限） |

## 7. 真机验证（关键的一步）

1. **完全退出** Clip Studio Paint（不是关文档，是退出程序）
2. 重新启动
3. 打开 `滤镜` 菜单，找 `红红子LAB → 一键灰度`
4. 选中一个栅格图层执行，确认画面变灰
5. 按 `Ctrl+Z` 确认可以撤销

### 如果没出现

不要反复重装。按下面顺序排查并记录：

1. 确认是 **EX** 版（PRO 不支持插件，这是官方限制）
2. 设环境变量 `REDCOLAB_LOG=1` 后重启 CSP，然后看 `%TEMP%\REDCOLAB.log`
   - **日志是空的** → CSP 根本没加载该文件 → 问题在**安装位置或扩展名**
   - **有 `[init]` 没有 `[filterInit]`** → 加载了但注册失败 → 把日志发我
3. 用 `-Clean` 重新安装，或反过来先只装 `.dll`、再只装 `.cpm`，逐个目录排除

---

## 8. 卸载

删除插件目录中的 `REDcoLAB.cpm` 与 `REDcoLAB.dll`，重启 CSP。

本插件：

- 不写注册表
- 不修改 CSP 配置文件
- 不常驻进程
- 不设置开机自启
- 不联网

---

## 9. 运行日志

默认**不写任何日志**。需要排查时：

```powershell
$env:REDCOLAB_LOG = "1"   # 然后重启 CSP
```

日志位置：`%TEMP%\REDcoLAB.log`

日志会记录：宿主版本、模块注册、滤镜注册、目标图层类型、通道排列、块数量、处理像素数，
以及每一种「安全退出」的原因（例如通道排列不支持）。

## 10. 常见构建错误

| 报错 | 原因与处理 |
|---|---|
| `missing sdk_official/` | 没有放 SDK 头文件；按第 2 节从官方页面获取 |
| `sdk_official/ is incomplete, missing: Xxx.h` | 头文件没放全，补齐列出的文件 |
| `g++ not found` | 按第 3 节安装 MinGW-w64；或把 `g++` 加到 PATH |
| `compile failed` 且指向 `#pragma TRIGLAV_PLUGIN_PACK` | 不应发生（已用 `-Wno-unknown-pragmas` 处理）；若出现请记录完整报错 |
| `does not export TriglavPluginCall` | 源码被改坏；检查 `TRIGLAV_PLUGIN_DLL_EXTERN` 是否还在 |
| `python not found` | 用 `-Python <绝对路径>` 指定 Python |
