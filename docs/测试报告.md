`REDcoLAB.cpm` 与 `REDcoLAB.dll` 两者结果一致，`run_tests.ps1` 退出码 `0`。

**逐项判读**：

- 第 1 个像素 `(200,40,90)` → `(78,78,78)`：Rec.709 计算值
  `0.2126*200 + 0.7152*40 + 0.0722*90 = 42.52 + 28.61 + 6.50 = 77.63 → 78`，**手工核对一致**。
- 第 2 个像素 `(10,220,30)` → `(162,162,162)`：`2.13 + 157.34 + 2.17 = 161.64 → 162`，一致。
- 第 3 个像素 `(90,90,200, alpha=0)` → **完全未变**：符合「跳过全透明像素」的设计。
- 所有像素第 4 通道（Alpha）与源数据**逐字节相同**：确认不修改透明度。
- `moduleKind = 0x4380` = `kTriglavPlugInModuleKindFilter`，与 SDK 定义一致。
- `targetKinds = 0x102, 0x101, 0x106` = RGBAlpha / GrayAlpha / BinarizationGrayAlpha，与源码一致。

## 3. 测试过程中发现并修复的真实缺陷

| # | 缺陷 | 现象 | 根因 | 处置 |
|---|---|---|---|---|
| 1 | 未判空宿主回调 | 模拟宿主 `filterRun` 阶段 `access violation writing 0x0` | 新实现直接调用 `TriglavPlugInFilterRunIsAlphaLocked`，而该宿主没有提供此回调，解引用空函数指针 | 新增统一宿主调用守卫，全部可选回调判空 + 安全默认值。记录见 `ERR-20261015-001` |
| 2 | PowerShell 5.1 编码 | 校验器误报 `no frontmatter`；`.ps1` 自身语法报错 | PS 5.1 按系统 ANSI 代码页读取 UTF-8 文件，中文变乱码且乱码字节含引号，破坏正则与语法 | 脚本改纯 ASCII；读 UTF-8 文件显式指定编码。记录见 `ERR-20261015-002` |
| 3 | 测试替身字符串传递 | `moduleID` / 菜单名读成 `None` | 新建的测试替身未沿用可用的句柄式字符串传递方式 | 改为句柄表方式，`str_of` 正确解析 |
| 4 | 误判透明像素 | 断言报告 `pixel 2 is not gray` | 断言把「alpha=0 按设计跳过」当成失败 | 断言拆分为「非透明像素必须变灰」+「透明像素必须原样」两条 |

> 第 1 条是**真实的健壮性缺陷**，不只是测试问题：同样的调用在真实 CSP 里如果宿主没提供该回调，会直接导致 CSP 崩溃。
> 旧版之所以没暴露它，只是因为它恰好没调用那个回调 —— 那是运气，不是正确性。
