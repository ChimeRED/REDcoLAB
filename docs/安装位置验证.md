## 2. 已收集的证据

| # | 证据 | 来源 |
|---|---|---|
| E1 | CSP 主程序二进制内含字面量 **`CLIPStudioPlugIn`** | 字节级扫描 `CLIPStudioPaint.exe` |
| E2 | `%APPDATA%\CELSYSUserData\CELSYS\CLIPStudioPlugIn\PAINT` **存在**，创建时间 `2025/5/14 15:10:57`，比 `CELSYSUserData` 根目录（`15:09:35`）仅晚 **82 秒** | 实测；时间差证明是 **CSP 自己创建的**，不是旧版留下的 |
| E3 | CSP 主程序内含 `CLIPStudioModule` + `PlugIn` 路径片段 | 字节级扫描 |
| E4 | CSP 主程序内含错误串 `PlugInError` / `PlugInNotFound` | 字节级扫描 |
| E5 | CSP 主程序内含宿主符号 `_TriglavPlugInHost`、`SExtensionModuleInitializeHost` | 字节级扫描 |
| E6 | **`.cpm` 字面量在 CSP 主程序中出现 0 次** | 整文件字节扫描 |
| E7 | Celsys 自带 40 个滤镜全部是 `PlugIn\PAINT\*.dll` | 实测目录 |
| E8 | Celsys 自带滤镜与我们的产物**导出同一个符号** `TriglavPluginCall` | 字节扫描对照 |

**由 E1 + E2 推断（推测，待本轮验证）**：`CLIPStudioPlugIn` 这个拼写与主程序里的字面量完全一致，
且该目录由 CSP 在首次运行时建立，因此它是最可能的用户插件加载位置。
注意它**不是** `CLIPStudioModule\PlugIn`（那是另一种拼写，同时也是旧版使用的位置）。

**由 E6 推断（推测，待本轮验证）**：`.cpm` 可能不是加载依据。
需要实测「`.dll` 能否被加载」以及「`.cpm` 能否被加载」。

## 3. 本轮验证方案（最稳路径）

一次装到**最可能的单一位置**，避免多目录互相干扰：

```powershell
cd C:\Users\Red04\Documents\deepseek-harness\default-workspace\REDcoLAB
powershell -NoProfile -ExecutionPolicy Bypass -File tools\install_plugin.ps1 -Only 1 -Execute
```

`-Only 1` 对应：

```
C:\Users\Red04\AppData\Roaming\CELSYSUserData\CELSYS\CLIPStudioPlugIn\PAINT
```

会把 `REDcoLAB.dll` 与 `REDcoLAB.cpm` **同时**放进该目录（两种扩展名一起放，
这样一次重启就能同时判断扩展名是否影响加载）。

然后：

1. **完全退出** Clip Studio Paint
2. 重新启动
3. 打开 `滤镜` 菜单，找 `红红子LAB → 一键灰度`

## 4. 结果判读表（请按实际填写）

| 观察结果 | 结论 | 下一步 |
|---|---|---|
| 菜单出现，且能正常灰度 | 位置 1 + 扩展名（两者之一或都可）有效 | 用「只留 `.dll`」再测一次，确定扩展名；然后写入手册与规则 |
| 菜单**未**出现，`%TEMP%\REDcoLAB.log` **为空** | 该位置无效（或扩展名无效） | 用 `-Only 6 -Execute` 试程序目录（Celsys 自带滤镜所在）；或改单扩展名重试 |
| 菜单**未**出现，日志有 `[init]` 无 `[filterInit]` | 已加载但注册失败 | 把日志发回，检查属性项注册逻辑 |
| 菜单出现但灰度无效果 | 加载成功，执行逻辑有问题 | 把日志发回（含 `[run]` 段） |

日志开启方式：

```powershell
$env:REDCOLAB_LOG = "1"    # 然后完全重启 CSP
# 日志：%TEMP%\REDcoLAB.log
```
