## 🔴 已确证结论（2026-10-16）

### 位置 [1] `%APPDATA%\CELSYSUserData\CELSYS\CLIPStudioPlugIn\PAINT` —— **不被加载**

**实测过程**：

1. 12:44:32–12:44:36 把 `REDcoLAB.cpm`、`REDcoLAB.dll`、`REDcoLAB_probe.dll` 装入位置 [1]，
   逐文件 SHA256 与源一致；
2. 其余候选目录确认无任何 REDcoLAB 文件（排除多位置干扰）；
3. 删除历史探针日志，确认用户 `%TEMP%` 中不存在该日志；
4. 用户在 **13:11:49** 启动了 CSP（证据：`CLIPStudioPaintVer1_5_0\ApplicationRestoringState.sqlite`、
   `RecentFiles\recentfiles` 于 13:11:51 被写入；`CLIPStudioPaint.exe` 最后访问时间 13:12:10）；
5. **结果：用户 `%TEMP%`（`C:\Users\Red04\AppData\Local\Temp`）中始终没有 `REDcoLAB_probe.log`。**
   其中唯一存在的那份位于 DSH 会话私有 TEMP（`...\Temp\dsh-jV3ofZ\`），是我自己跑测试时写的。

**为什么这个证据是决定性的**：探针在 `DllMain` 的 `DLL_PROCESS_ATTACH` 分支就**无条件**写一行日志。
只要 DLL 被映射进 CSP 进程，日志必然出现——不需要宿主调用入口点。
日志不存在 ⇒ **CSP 根本没有打开这个文件**。

**结论**：`CLIPStudioPlugIn\PAINT` 这个目录不参与第三方滤镜插件的扫描加载。
尽管它的名字与主程序内字面量 `CLIPStudioPlugIn` 一致、且由 CSP 自建，但实测证明它不是加载点。

> 这也**推翻了旧版 v0.1.6 的核心假设**——旧版把插件放进 `CLIPStudioModule\PlugIn\PAINT\win`，
> 与位置 [1] 同属「用户数据目录」这一类，很可能同样不被扫描。这解释了它为什么「装了没用」。

## 2. 为什么用「探针」而不是直接装产品

产品版只在 `REDCOLAB_LOG=1` 时才写日志，而且它的日志内容与**我自己在模拟宿主上跑出来的日志一模一样**
—— 无法区分「CSP 加载了」和「我测试时写下的」。

探针解决了这个歧义：

| 特性 | 产品版 | 探针版 |
|---|---|---|
| 是否总是写日志 | 否（需环境变量） | **是，无条件** |
| 日志开头标志 | 无 | **`*** CSP LOADED THE FILE ***`** |
| 是否修改画面 | 是（这就是它的功能） | **否，一个像素都不改** |
| 是否打印宿主能力清单 | 否 | **是，逐个列出每个回调是否存在** |
| 参数面板 | 8 算法 + 强度 | 无（故意最简，避免失败被归咎于参数注册） |

所以：**探针的日志里出现 `*** CSP LOADED THE FILE ***`，就等于证明 CSP 加载了这个文件。**
这是模拟宿主无法伪造的证据。

## 5. 探针日志长什么样（在模拟宿主上的真实样例）

```
=============================
PROBE DLL_PROCESS_ATTACH at REDcoLAB_probe
=============================
PROBE selector=0x101 data=... server=...
PROBE === moduleInitialize ===
  *** CSP LOADED THE FILE *** (this line only appears in a real host)
  hostObject = ...
  recordSuite:
    moduleInitializeRecord                 present
    filterInitializeRecord                 present
    filterRunRecord                        present
    filterActivationInitializeRecord       NULL
    filterActivationRunRecord              NULL
  serviceSuite:
    stringService                          present
    bitmapService                          NULL
    offscreenService                       present
    propertyService                        present
    offscreenService2                      NULL
    propertyService2                       present
  ...
```

`filterActivationInitializeRecord` / `filterActivationRunRecord` 在模拟宿主上是 NULL
（那个测试替身没实现它们）。**真实 CSP 上这两项的取值本身就是有价值的证据** ——
它决定了插件登记为 `Filter(0x4380)` 还是 `FilterActivation(0x5530)`。

## 7. 已收集的二进制证据

| # | 证据 | 来源 |
|---|---|---|
| E1 | 主程序内含字面量 **`CLIPStudioPlugIn`** | 字节级扫描 `CLIPStudioPaint.exe` |
| E2 | 位置 [1] 由 CSP 创建（创建时间比 `CELSYSUserData` 根只晚 82 秒） | 文件时间戳 |
| E3 | 主程序内含 `CLIPStudioModule` + `PlugIn` 路径片段 | 字节级扫描 |
| E4 | 主程序内含 `PlugInError` / `PlugInNotFound` 错误串 | 字节级扫描 |
| E5 | 主程序内含宿主符号 `_TriglavPlugInHost`、`SExtensionModuleInitializeHost` | 字节级扫描 |
| E6 | **`.cpm` 字面量在主程序中出现 0 次** | 整文件字节扫描 |
| E7 | Celsys 自带 40 个滤镜全部是 `PlugIn\PAINT\*.dll` | 目录实测 |
| E8 | 我们的产物与 Celsys 自带滤镜**导出同一符号** `TriglavPluginCall` | 字节扫描对照 |

**E6 是同时提供 `.dll` 与 `.cpm` 两种产物的原因**，也是旧版很可能失败的根因：
旧版只装了 `.cpm`，且从未重启 CSP 验证过加载。
