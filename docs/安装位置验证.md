## 3. 之前三次「未被加载」的结论是**错的** —— 原因与纠正

### 错误结论

前三轮我根据「真实 `%TEMP%` 中不存在探针日志」判定：
位置 [1] 与位置 [6] 均未被加载，并据此写成「手动放文件在 5.0.4 上不成立」。

### 真正原因

**CSP 进程继承了 DSH 会话的 `TEMP` 环境变量。** 我用 `Start-Process` / 用户从 DSH 环境启动 CSP 时，
`TEMP` 指向沙箱私有目录：

```
C:\Users\Red04\AppData\Local\Temp\dsh-jV3ofZ\
```

探针按 `%TEMP%` 写日志，因此日志**确实产生了**，只是写进了那个沙箱目录，
而我一直检查的是真实用户 `%TEMP%`（`C:\Users\Red04\AppData\Local\Temp`）。

**这是取证方法的缺陷，不是插件的缺陷。** 我在那个沙箱目录里找到的 38019 字节日志
当时被我误判为「我自己测试写的」——实际上它混合了模拟宿主与真实 CSP 两种记录，
而我用 `hostObject`/`hostVersion` 区分时判断标准不够严（模拟宿主也有 `hostVersion=1` 的记录，
真实 CSP 的记录夹杂其中，我按分段统计时把两者混在了一起）。

### 纠正后的方法论教训

1. **不要假定 `%TEMP%` 是宿主实际使用的目录。** 被启动进程的环境继承可能改变它。
2. 判定「是否加载」应当**同时扫描所有可能的 TEMP 位置**，而不只是预期的那个。
3. 更强的证据是**让宿主自己留下无法伪造的痕迹**：`hostVersion=6` 这一点就足够，
   因为模拟宿主固定为 1。

## 6. 复现方式（非沙箱环境下）

```powershell
# 1) 构建
powershell -NoProfile -ExecutionPolicy Bypass -File tools\build.ps1

# 2) 装到唯一被确证的位置
copy dist\REDcoLAB.dll "C:\build\csp\CLIP STUDIO 1.5\CLIP STUDIO PAINT\PlugIn\PAINT\"

# 3) 完全退出后重启 CSP
# 4) 若要看日志：启动前设 REDCOLAB_LOG=1，日志在 %TEMP%\REDcoLAB.log
```

> ⚠️ **特别注意**：`REDcoLAB.dll` 放在 Celsys 自带滤镜的同一目录。
> 卸载时只需删除该文件；它不会修改 CSP 任何原有文件。
> **CSP 升级或修复安装可能会移除该文件**，升级后需重新安装。
