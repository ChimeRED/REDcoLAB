## 2. ⚠️ 更正：前三轮的「未被加载」结论是错的

### 我先前写下的错误结论

前三轮我依据「真实 `%TEMP%` 中不存在探针日志」判定位置 [1] 与位置 [6] 均未被加载，
并进一步写成「手动放文件在 5.0.4 上不成立」「旧版失败源于安装方式」。

**这些结论是错的，现予撤回。**

### 真正原因：TEMP 路径被沙箱改写

**CSP 进程继承了启动者的 `TEMP` 环境变量。** 在 DSH 会话中启动 CSP 时：

```
TEMP = C:\Users\Red04\AppData\Local\Temp\dsh-jV3ofZ\     ← 沙箱私有目录
```

探针按 `%TEMP%` 写日志，**日志确实产生了**，只是写进了沙箱目录；
而我一直检查的是真实用户 `%TEMP%`（`C:\Users\Red04\AppData\Local\Temp`），因此看不到，
进而误判为「未被加载」。

更早时我确实在沙箱目录里发现过一份 38019 字节的探针日志，但当时我按段统计
`hostObject`/`hostVersion` 时判断标准不够严（模拟宿主与真实 CSP 的记录混在同一文件里），
把它整体当成了「我自己测试写的」，错过了里面的真机记录。

### 方法论教训（已写入 `ai-toolkit/AGENTS.md`）

1. **不要假定 `%TEMP%` 是宿主实际使用的目录** —— 被启动进程的环境继承可能改变它。
2. 判定「是否加载」必须**同时扫描所有可能的 TEMP 位置**，而不是只看预期的那个。
3. 更强的判据是**宿主自己无法伪造的痕迹**：`hostVersion=6` 这一点就足够。

## 5. 复现方式

```powershell
# 1) 构建
powershell -NoProfile -ExecutionPolicy Bypass -File tools\build.ps1

# 2) 装到已确证的位置（install_plugin.ps1 -Only 1 现在默认指向它）
powershell -NoProfile -ExecutionPolicy Bypass -File tools\install_plugin.ps1 -Only 1 -Execute

# 3) 完全退出后重启 CSP
# 4) 需要日志时：启动前设 REDCOLAB_LOG=1，日志在 %TEMP%\REDcoLAB.log
```

> ⚠️ **注意事项**
> - `REDcoLAB.dll` 放在 Celsys 自带滤镜的同一目录。它**不修改 CSP 任何原有文件**，删除该文件即卸载。
> - **CSP 升级或修复安装可能移除该文件**，升级后需重新安装。
> - 需要写入 CSP 程序目录，通常**需要管理员权限**。
