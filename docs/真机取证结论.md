# 真机加载取证结论文档

- 版本：1.0.0
- 记录时间：2026-10-16
- 目的：**明确回答「REDcoLAB 究竟能不能在 CSP 里用」**，不回避、不含糊。

---

## 0. 一句话结论

**代码侧全部完成并通过验证；但「插件被 CSP 加载」这一步在本机 CSP 5.0.4 上未能成功，
因此「一键灰度」功能目前处于「无法确认可用」状态。**

这不是代码缺陷的结论，而是**安装/加载机制**未走通的结论。

---

## 1. 已确证的否定结果（两次真实 CSP 启动）

| 测试 | 探针位置 | CSP 启动证据 | 探针日志 | 判定 |
|---|---|---|---|---|
| 第 1 次 | 位置 [1] `%APPDATA%\CELSYSUserData\CELSYS\CLIPStudioPlugIn\PAINT` | 13:11:49（`ApplicationRestoringState.sqlite`、`recentfiles` 13:11:51 写入） | 真实 `%TEMP%` 中**无** | **未被加载** |
| 第 2 次 | 位置 [6] CSP 程序目录 `PlugIn\PAINT`（自带 40 个滤镜同处），仅 `.dll` | 13:15:05–13:15:50（`DocumentOpen_paint.cmdb` 13:15:05、`SubView\default.psv` 13:15:50） | 真实 `%TEMP%` 中**无** | **未被加载** |

### 判定依据（为什么「无日志」等于「未加载」）

探针在 `DllMain` 的 `DLL_PROCESS_ATTACH` 分支**无条件**写一行日志：

```cpp
if (reason == DLL_PROCESS_ATTACH) {
    ::DisableThreadLibraryCalls(module);
    PROBE("PROBE DLL_PROCESS_ATTACH at %s\n", "REDcoLAB_probe");
}
```

**只要 DLL 被映射进 CSP 进程，这行日志就必然出现**，完全不需要宿主调用入口点。
因此「日志不存在」严格等价于「CSP 没有打开这个文件」。

### 结果的确定性范围

| 结论 | 确定性 |
|---|---|
| 位置 [1] 不被加载 | **确定**（测试完整执行，无历史日志污染） |
| 位置 [6] 放 `.dll` 不被加载 | **确定**（测试完整执行如上） |
| `.cfpi` / `.cpm` 扩展名是否有效 | **未测试**（变体放入时间晚于最后一次 CSP 启动，无判定数据） |
| 第 2 次是否为「完全退出后重启」 | **无法确认**（文件时间戳不能区分「完全重启」与「关闭后再打开」） |

## 2. 这解释了旧版的失败

旧版 v0.1.6 把插件放进 `%APPDATA%\CELSYSUserData\CELSYS\CLIPStudioModule\PlugIn\PAINT\win`，
与位置 [1] 同属「用户数据目录」一类。

**它「装了没用」不是代码问题，而是安装方式在本机 CSP 上不成立。**

旧版自己的说明文件里也写着「未在真实 CSP 中验证 —— CSP 是在插件安装前启动的」。
这正是本项目坚持要做真机取证的原因：**没有真机证据的「已完成」是站不住的。**

## 3. 与官方资料的张力（如实记录）

| 来源 | 说法 |
|---|---|
| CSP 官方滤镜插件 SDK 文档 | 构建出插件文件后放入 CSP 插件目录，重启即出现 |
| 第三方开发者实录（2017，CSP 1.x 时代） | 复制 `.cpm` 到 `Documents\CELSYS\CLIPStudioModule\Plugin\PAINT`，重启后滤镜菜单出现条目 |
| **本机实测（CSP 5.0.4）** | **上述流程未复现成功** |

本机 CSP 5.0.4 的目录结构与 1.x 时代已不同（`CLIPStudioPlugIn` 与 `CLIPStudioModule` 两种拼写并存），
**上述历史资料不能直接套用到 5.0.4。**

## 4. 官方插件实际如何安装（二进制证据）

| 证据 | 说明 |
|---|---|
| 官方 `.cfpi` 文件**本身就是 PE 可执行文件**（前 2 字节 `4D 5A`） | `TGCxsPlugIn.cfpi` / `TGXPGPlugIn.cfpi`，是**独立进程**，不是被载入的 DLL |
| 主程序内 `cfpi` 字面量**只出现 1 次**，且在 `timelapse...cfpi` 这类无关字符串中 | CSP **不按 `.cfpi` 扩展名扫描目录** |
| 主程序含 `PlugInError` / `PlugInNotFound` 错误串 | 存在插件错误提示路径 |
| `CLIPStudioModule` 出现在**配置键列表**（`PlugIn`、`CategoryFolderPath`、`DataFolderPath`） | 是配置项，不是路径拼接代码 |
| 主程序含**文件插件**符号 `FPWFilePlugInEntryPoint` / `PlugInUuid` / `PlugInFileKind` | CSP 存在滤镜以外的插件形态 |
| 官方插件商店流程要求**通过 CLIP STUDIO 安装并在线上做许可认证** | 官方插件的分发与安装走这条通道 |

### 推测（明确标注：未验证）

CSP 5.0.4 可能**只加载内置滤镜**；第三方插件必须经 CLIP STUDIO 的安装 + 许可认证流程，
安装到 CSP 约定的位置，**而非手动放入目录**。

**这个推测我没有验证过**，它只是与现有证据最一致的解释。要确认它需要：
观察一次官方插件（如 PDF 入出力插件）被安装时，CSP 目录里到底发生了什么变化。

## 6. 下一步的确定路径（若要继续推进）

按代价从低到高：

1. **补跑三种扩展名测试**（零成本）：探针已以 `.dll` / `.cfpi` / `.cpm` 三种扩展名放在程序目录，
   一次**完全退出后重启**即可判定扩展名是否影响加载。
2. **观察官方插件的安装行为**（低成本，信息量大）：
   通过 CLIP STUDIO 安装一个官方免费插件（如 PDF 入出力插件），
   对比安装前后 CSP 目录与用户数据目录的变化，即可看出真实加载位置与格式。
3. **向 Celsys 官方确认**（成本中）：SDK 使用许可契约书第 10 条规定 Celsys 会尽力回应 SDK 使用咨询。
   直接询问「5.0.4 上第三方滤镜插件的正确安装位置与格式」是最权威的途径。
4. **等待公开的其它插件形态 SDK**：主程序中确认存在文件插件（`FPWFilePlugInEntryPoint`），
   但公开 SDK 未覆盖。**不会通过逆向私有格式实现** —— 那属于非公开接口，被项目规则禁止。
