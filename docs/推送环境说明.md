# 推送与发布环境说明

本机在「推送 GitHub」这件事上有几个非默认的坑，都是实际踩到并解决的。
记录下来，避免下次重新试错。`tools/archive.ps1` 已把这些处理内置。

---

## 1. schannel 后端不可用 → 必须用 OpenSSL

**现象**

```text
git push origin main
fatal: unable to access 'https://github.com/ChimeRED/REDcoLAB.git/':
schannel: AcquireCredentialsHandle failed: SEC_E_NO_CREDENTIALS (0x8009030e)
```

`curl.exe` 也是同一个错，`Invoke-WebRequest` 访问任何 HTTPS 站点都失败
（`基础连接已经关闭`）。证书存储本身可读（`Cert:\LocalMachine\Root` 有 91 张证书），
所以不是证书缺失，而是 **schannel 在这个执行环境里拿不到凭据上下文**。

**解决**：改用 OpenSSL 后端，它自带 CA 证书库，不走 schannel。

```powershell
git -C <repo> config --local http.sslBackend openssl
```

已写入 REDcoLAB 仓库的本地配置（在 `C:\Users\Red04\AppData\Local\redkolab-tools\git\ucrt64\etc\ssl\certs\` 下有 `ca-bundle.crt`）。

验证：`git ls-remote --heads origin` 由失败变为成功。

---

## 2. 没有凭据管理器 → 推送拿不到账号

**现象**

```text
fatal: could not read Username for 'https://github.com': No such file or directory
```

便携版 git 没有安装 Git Credential Manager，`git push` 无法交互式索要账号密码。

**解决**：`gh` 已经处于登录态（账号 `ChimeRED`，token 权限含 `repo`），
用它的 token 构造一次性的推送 URL：

```powershell
$token = (gh auth token).Trim()
git -c http.sslBackend=openssl push "https://x-access-token:$token@github.com/ChimeRED/REDcoLAB.git" main:main
```

**注意**：token **不写入任何配置文件、不落盘、不打印**。
`archive.ps1` 里的 `Get-PushUrl` 就是这么做的，用完即弃。

---

## 3. `gh` 需要 git 在 PATH 上

**现象**

```text
gh release create ...
unable to find git executable in PATH; please install Git for Windows before retrying
```

**解决**：把便携 git 目录临时加到 PATH：

```powershell
$env:PATH = "$env:LOCALAPPDATA\redkolab-tools\git\cmd;$env:LOCALAPPDATA\redkolab-tools\git\bin;$env:PATH"
```

---

## 4. `gh release` 必须在仓库目录内运行

**现象**

```text
no git remotes found
```

**解决**：`gh` 从「当前工作目录的 git remote」推断仓库，所以要先 `Set-Location` 到项目目录。

---

## 5. git 提交身份

新初始化的仓库没有身份配置，`git tag` / `git commit` 会报
`Committer identity unknown`。

REDcoLAB 仓库已配置为与旧版一致：

```
user.name  = ChimeRED
user.email = ChimeRED@users.noreply.github.com
```

---

## 6. 代理

旧版仓库配置了本地代理 `http://127.0.0.1:7890`，REDcoLAB 仓库沿用同一配置
（`http.proxy` / `https.proxy`，仅本仓库 local 配置，不改全局）。
该端口在本机可用。

推送时偶发 TLS 瞬断（`unexpected eof while reading`），**重试即可**，
不要因此改动任何网络配置。`archive.ps1` 的推送步骤失败会明确报错并保留本地提交与标签。

---

## 7. 关于强制替换远端

本次用 `--force-with-lease=<ref>:<旧sha>` 替换了远端 `main`
（旧版提交 `561596a` → 新版 `25b6e59`）。

**为什么这次可以**：替换前已核对

1. 远端**只有** `main` 一个分支，**没有**任何标签、**没有**任何 Release；
2. 远端 `main` 的 HEAD 与本地旧版仓库 HEAD **完全相同**（`561596a`），
   即远端没有旧版本地之外的内容；
3. 旧版已完整冻结在 `_baseline/legacy-v0.1.6/`（git bundle 全历史 + 工作树快照 + 未提交改动 diff）。

三条都成立，替换才**无损失**。

**今后规则**：`archive.ps1` 的常规发布**不使用**任何 force 选项，
只在正常的快进推送下工作。若哪天需要再次替换历史，必须先重复上面三步核对。
