# A / C / D 三项功能的可行路径

- 用途：记录「导航器实时投影」「独立叠加剪切蒙版」「统一控制面板」这三项的**可达路径**。
- 前提结论：**在 CSP 插件路线下这三项都无解**，因为官方 Filter Plug-in SDK 里没有对应接口。
  本文档给出的是**不依赖插件**的合规做法。

---

## 0. 为什么插件路线无解（一句话版）

官方 SDK 能调用的函数只有 `TriglavPlugInRecordSuite` 里的三组
（moduleInitialize / filterInitialize / filterRun），其余是 `reserved` 空位。
整个 SDK 里与「图层」相关的只有一个 `getLayerOriginProc`（取当前图层原点）。
**没有**导航器、视图状态、画布变化通知、图层枚举、蒙版、面板宿主、快捷键注册。

---

## A. 导航器实时投影

### 插件路线：不可行

- SDK 无导航器 / 视图缩放平移状态 / 画布变化通知的接口。
- 滤镜只在被调用那一次运行，处理完即返回，**没有地方挂载事件监听**。
- 因此即使能拿到画面也没有「内容变了通知我」的机制，只能轮询 —— 而屏幕抓取是被明令禁止的。

### 可达路径：用 CSP 原生的「副视图」（Sub View）

**这才是正解，而且完全满足原始诉求。**

| 你的原始要求 | 副视图的实际情况 |
|---|---|
| 实时或尽可能及时显示当前画布内容 | 实时镜像画布显示内容 |
| 随绘制结果变化而更新 | 随画布更新 |
| 尽可能同步缩放、平移及视图状态 | 同步 |
| 低 CPU / GPU / 内存占用 | 复用 CSP 已渲染的数据，是内部渲染路径，**不经过任何抓屏** |
| 只承担预览，不需要在其中绘画/编辑 | 副视图本身就是纯查看面板 |

**打开方式**：CSP 的 `窗口` 菜单 → 勾选 `副视图`。
（具体菜单文案与位置请以你机器上的实际版本为准；我没有在本会话中通过 UI 验证过菜单层级。）

原有的**导航器**面板本身也已经是低开销实时预览，可作为第二种选择。

### 唯一无解的部分

「把它嵌进 CSP 窗口后**由第三方接管渲染**」——这需要 Celsys 开放新 SDK。
现有公开 SDK 做不到，我不会用独立窗口冒充。

## C. 独立叠加剪切蒙版

### 先澄清一件事：嵌套剪切，CSP 原生本来就支持

你描述的层级（C 剪切到 B、B 剪切到 A，形成嵌套）**用原生「用下一图层剪切到图层」就能搭出来**：

```
A   基础图层
B   用原生剪切到 A
C   用原生剪切到 B      ← 运行时就是嵌套合成
D   用原生剪切到 C      ← 可继续加深
```

**不需要任何插件。** 如果你要的只是这个层级效果，现在就能做。

### 插件路线为什么给不了「独立的那一套」

你要的是「**独立于原生的另一套**剪切系统」——插件自己维护一组剪切关系，与原生那套并存、可区分、图层改动后仍有效。

SDK 拿不到图层列表，因此：

- 无法枚举图层（连有哪些图层都不知道）
- 无法读取或设置原生剪切开关与目标
- 无法创建或组合蒙版
- 无法监听图层增删来维护关系

### 能逼近的合规做法（都不是「独立嵌套剪切」）

| 做法 | 效果 | 局限 |
|---|---|---|
| **图层蒙版**：给 C 加蒙版，蒙版形状取自 B 的 Alpha | 效果上等价于「C 被 B 剪切」，**且独立于原生剪切开关，两者可同时存在** | 需要手动生成蒙版；不是可编辑的「关系」 |
| **图层文件夹分组**：把一组剪切关系关进文件夹，再对文件夹整体做剪切 | 形成多段独立剪切，互不干扰 | 依赖原生剪切，不是独立系统 |
| **先合并再剪切** | 能做出任意层级的合成结果 | **有损**，需先备份；失去可编辑性 |

**我不会**用普通文件夹、图层合并或预烘焙图像**冒充**「独立嵌套剪切关系」——那正是被禁止的做法。

### 真正的出路

只有 Celsys 开放图层相关的插件接口（或提供文件插件 SDK）才可能实现。
公开的 Filter Plug-in SDK 不会再有变化 —— 官方要望板上 2013 年就有同样请求，2019 年该板已关闭，从未落地。

## D. 统一控制面板

### 插件路线：部分可行

| 需求 | 结论 |
|---|---|
| 参数设置界面 | **可行** —— 滤镜自己的模态对话框 |
| 功能启用/停用开关 | **可行** —— 做成参数项 |
| 设置保存、重启恢复 | **可行** —— `setItemStoreValueProc` |
| 常驻停靠面板 | **不可行** —— SDK 无面板宿主接口 |
| 插件注册全局快捷键 | **不可行** —— 只能由 CSP 的快捷键设置分配 |

### 可达路径：把滤镜入口编排进 CSP 原生面板

CSP 原生提供常驻、可停靠的面板机制，用它们承载「统一控制面板」的角色：

| 原生机制 | 作用 |
|---|---|
| **自动动作（Auto Action）** | 常驻可停靠面板；能编排成动作序列，一键跑多个操作；可给动作分配快捷键 |
| **快速访问（Quick Access）** | 常驻可停靠面板，集中放常用命令 |
| **快捷键设置** | 给滤镜与自动动作分配按键（这是插件做不到、CSP 能做到的部分） |
| **工作区（Workspace）** | 把上述面板的布局整体保存与恢复 |

**推荐组合**：把 REDcoLAB 的滤镜（`滤镜 → 红红子LAB → 一键灰度`）加入一个自动动作，
再把该动作放上快速访问面板，并分配快捷键。这样得到的就是一个常驻的统一入口，
插件自己只负责参数对话框。

> 具体菜单文案与可编排项请以你机器上的实际版本为准；本会话未通过 UI 验证这些面板的细节。

## 附：另一条技术路线存在，但 SDK 未公开

在 CSP 主程序二进制中扫到两类符号，说明 **CSP 确实有滤镜之外的插件形态**：

| 排查到的符号 | 含义 |
|---|---|
| `FPWFilePlugInEntryPoint` / `PlugInUuid` / `PlugInFileKind` | **文件插件**入口与记录字段 |
| `TGCxsPlugIn.cfpi`、`TGXPGPlugIn.cfpi`、`TGMaterialPlugIn.cfpi`、`TGTosPlugIn.cfpi` | 官方自带的**文件格式插件**（`.cfpi` + 配套 DLL） |

也就是说，**文件插件**是一类真实存在的 CSP 插件。

**但**：公开的只有 **Filter Plug-in SDK**。文件插件的 ABI、`.cfpi` 清单格式、
加载与签名规则**没有公开文档**。要合法走这条路，需要 Celsys 开放对应 SDK 或书面授权。

**我不会**通过逆向私有格式、读内存或注入等方式去实现 —— 那属于非公开接口，被项目规则禁止。

---

## 汇总结论

| 功能 | 插件路线 | 可达路径 |
|---|---|---|
| A 导航器实时投影 | 不可行 | **用原生「副视图」/导航器面板**（已满足全部性能诉求，零开发成本） |
| C 独立叠加剪切蒙版 | 不可行 | 嵌套剪切用**原生剪切**即可；「独立那一套」可用**图层蒙版**逼近，或等 Celsys 开放接口 |
| D 统一控制面板 | 部分可行 | 插件做参数对话框；常驻入口用**自动动作 + 快速访问 + 快捷键** |
